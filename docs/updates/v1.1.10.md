# v1.1.10: End-city chests open as personal Lootr chests

## Same instance, same update workflow

Keep your existing Prism instance and press **Play**. The pre-launch command
is unchanged and runs Packwiz with `-g -s client`. The public all-in-one ZIP
is for **new installs**, not a required reimport for existing players.

GoldClaim 1.0.41 is `side = "server"` in Packwiz, so clients download nothing
new and no client configs change. Personal `options.txt` (keybindings and
resource-pack selections), `optionsof.txt`, `optionsshaders.txt`,
`servers.dat`, `servers.dat_old` and Default Options journals remain excluded
from updates. Default Options still applies only to missing first-run settings.

## Fix

On v1.1.9, BetterEnd chests in RSW End cities could not be opened. The server
logged `... is missing its Lootr conversion tag` and cancelled the interaction.

Cause: the live server has two data packs named `gangs_fixes`:

- `config/paxi/datapacks/gangs_fixes` is the current pack-managed Paxi pack.
  It contains the `lootr:convert/chests` entries for BetterEnd chests.
- `global_packs/required_data/gangs_fixes` is a legacy server-only Global
  Packs copy with an old load function.

Pack IDs are unique, so the legacy copy shadows the Paxi pack. Lootr never
sees the BetterEnd tag entries. GoldClaim 1.0.40 treated the missing tag as
fatal.

GoldClaim 1.0.41:

- If Lootr's tag-based lookup has no replacement, converts plain BetterEnd
  chests directly to Lootr's chest. It keeps the original facing,
  waterlogging, loot table, seed and custom name, and makes the chest single.
  Trapped and non-chest containers are not converted this way.
- Never makes a chest unusable. If conversion still fails, it logs the error,
  restores the original chest and opens it normally.
- Leaves the earlier safeguards unchanged. Already-opened, player-filled,
  locked or existing Lootr chests are untouched, and Lootr's disable,
  dimension, blacklist and world-border settings are respected. Chests opened
  as shared chests before this fix are not refilled.

The duplicate pack ID is **not** changed in this release. Removing the legacy
copy would also activate the rest of the Paxi `gangs_fixes` pack on live,
including the RSW Nether dimension type, True Ending functions, blood-moon
event settings and furniture bin loot. Those need the owner's approval and
their own test first.

## Server deployment

Nothing is deployed by publishing. Choose one path:

- **Next normal restart (running server untouched):** stage with
  `scripts\Stage-GameplayHotfix.ps1 -GameDirectory '<server>' -Version 1.0.41`.
  On the next start, the existing launcher hook verifies the checksums. It
  backs up GoldClaim 1.0.40 to `mod-backups/gameplay-1.0.41`, then installs
  1.0.41. Rollback: restore that jar, remove 1.0.41 and restore
  `start.bat.bak_before_goldclaim_1.0.41`.
- **Stopped-server payload:** the v1.1.10 ZIP's `server-update` installs
  checksum-pinned GoldClaim 1.0.41 and updates the launcher pin.

GoldClaim SHA256:
`fb680c2fd5b807a8e72afe8b1e1967f5bf45a4d07b45a10dea1b02d2b4df9116`.

## Validation

- Ran a production End-city fixture with Lootr Fabric 0.7.35.86 and BetterEnd.
  It used the 17 real `lacugrove_chest` markers from the `ship`,
  `fat_tower_top` and `third_floor_2` templates.
  - Tags present: every chest opened as a personal Lootr chest.
  - Tags removed to reproduce live: the fixture asserted Lootr returned no
    replacement, and every chest still opened as a personal Lootr chest.
  - In both modes, chest facing, loot tables and seeds were preserved, two
    players got independent populated inventories, and already-opened and
    player storage stayed untouched.
- Gradle unit tests and build passed.
- Staging, install, repeat start, corruption rejection and post-stage edit
  rejection passed for 1.0.39, 1.0.40 and 1.0.41.
- Release ZIP, client auto-update preference retention, installer tests and
  Packwiz hashes were validated as in [v1.1.9](v1.1.9.md).
