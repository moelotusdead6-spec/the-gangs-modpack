# v1.1.9: Kits, reachable End cities, BetterEnd biomes and personal loot

## Same instance, same update workflow

Keep your existing Prism instance and press **Play**. The pre-launch command
is unchanged and runs Packwiz with `-g -s client`. Failed updates block launch
and appear in Prism's log. The public all-in-one ZIP is for **new installs**,
not a required reimport for existing players.

Instances without the hook still need the one-time setup in the
[update guide](README.md). This release does not change Minecraft, Java or
Fabric Loader requirements.

GoldClaim 1.0.40 is `side = "server"` in Packwiz. No client mod changes are
needed. Two pack-managed gameplay configs change:

- `config/paxi/datapacks/gangs_kits/data/gangs/loot_tables/kits/monthly.json`
- `config/randomcollections/config.json`

These are reward definitions, not personal settings. Other managed mod
configs remain managed by Packwiz, while untracked personal mod configs are
left alone. Do not copy the complete config directory over an existing game.

Personal `options.txt` (including keybindings and resource-pack selections),
`optionsof.txt`, `optionsshaders.txt`, `servers.dat`, `servers.dat_old` and
Default Options journals are excluded from Packwiz updates. Default Options
18.0.6 and its existing templates remain unchanged: they supply defaults only
when the corresponding personal saved settings are missing. They are not a
settings migration, replacement or backup mechanism.

## Server gameplay fixes

### Kits and Endermen

- Removes the unregistered `doapi:standard` reward that invalidated the
  Monthly table, corrects stale bow/wand/staff IDs and replaces the unavailable
  BetterNether staff with the installed Netherite fire staff.
- Failed kit claims report directly to the player even through silent
  console execution. Full inventories do not receive partial rewards or
  consume the claim. Unlocks, scores and 30-day cycles are not reset.
- Removes the local Enderman spawning balance/rarity bypass. Original
  Enderman Overhaul spawning is restored; existing entities are untouched.

### At least seven reachable cities on future resets

Before RSW reopens, GoldClaim finds and generates at least seven natural End
cities, validates their actual bounds, and saves their chunks. Each complete
city must fit at least 16 blocks inside the existing 10,000-block-diameter
border, outside the central 1,024-block radius and within build height.
Reserved cities are at least 512 blocks apart.

Terrain/biome eligibility and normal treasure generation remain intact.
Seven ships are not promised, and additional natural cities are not capped.
Insufficient cities are a logged reset failure that leaves RSW closed, not a
successful reset with unreachable structures. Interrupted preparation is
rechecked after restart. Gateway and BetterEnd deferred-treasure fixes from
the earlier local hotfixes are retained.

### Primarily BetterEnd outer-island land

Future RSW End resets select the separately serialized `gangs:rsw_end`
generator. BetterEnd has 87.5% of outer-island biome-selection weight;
other eligible biomes share 12.5%, retaining their relative weights.
Nullscape's islands in outer void/barrens noise regions use that same map.
The central island, terrain/noise settings, border and other dimensions stay
unchanged. This is a weighted target, not an exact percentage on every seed
or local flight path.

Installation does not change the current End generator or regenerate chunks.
The new policy starts on the **next normal RSW reset after installation**,
then persists across subsequent starts through Multiworld's custom generator.
The reset schedule is unchanged; no early reset is required.

### BetterEnd city chests use Lootr before first opening

The conversion tags were already correct. Lootr's background conversion waits
for a surrounding 5x5 area of fully loaded chunks. A player opening a chest
before conversion could generate shared inventory and consume its loot table
permanently.

GoldClaim now converts eligible unopened natural BetterEnd chests in RSW End
on first opening, before the table is consumed, then opens Lootr's normal
personal inventory. Loot tables, seeds, facing, waterlogging and custom names
are preserved. Lootr's conversion setting, dimension/table blacklists and
configured border restriction are honored.

This covers existing **unopened** city chests without a reset. Already-opened
shared loot, nonempty/locked containers, player storage and existing Lootr
identities are not converted or refilled. Other dimensions are unchanged.

## Separate stopped-server payload

Publishing does not install anything on the live server or restart it.
At the next scheduled restart, stop the server and make a world backup,
then run from the extracted ZIP:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\server-update\Install-ServerUpdate.ps1 -GameDirectory "C:\path\to\server"
```

The installer requires Java 17+ (`-JavaExecutable` can select it), backs up
touched files, installs checksum-pinned GoldClaim 1.0.40 and both repaired
reward configs, and retains the earlier policy/compatibility updates.
It never starts the server. **Do not pass `-ResetRswEnd`.** The full config
tree is supplied for new installs/reference, not wholesale copying.

The locally staged 1.0.40 startup hotfix is compatible with these same final
jar/config hashes; its next invocation can finish without downgrading or
resetting anything. Existing worlds, player data, claims, kit state, the
RSW reset journal and the current End generator are preserved.

Chest and kit fixes activate at the next start. Biome dominance and city
readiness apply on subsequent resets. After a reset persists
`custom_generator: gangs:rsw_end`, do not remove/downgrade the codec blindly:
retain 1.0.40 or plan a compatible generator migration.
