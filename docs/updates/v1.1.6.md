# v1.1.6: disposable RSW, BetterEnd compatibility and Lootr

## Backup policy

No completed RSW reset backups are retained. GoldClaim 1.0.34 moves the old
three worlds and their Multiworld configs to temporary transaction storage
outside the active world tree, then deletes that transaction once replacement
worlds and persisted seeds have been verified. Interrupted transactions remain
recoverable; the saved reset journal and next-reset schedule are unchanged.
Legacy in-world transactions are also cleaned when they complete.

RSW Waystones removal no longer copies region/entity/POI files. Wild cleanup
still preserves its original regions, registry, plan and completion marker.
The stopped-server installer removes old RSW reset archives and RSW-only data
from previous policy/Waystones backups. It never resets active worlds without
the explicit `-ResetRswEnd` switch; that switch now deletes the End without
retaining an RSW backup.

Server update-file backups and other timestamped server backup categories
retain at most two generations each. `Prune-ServerBackups.ps1` can also be run
against a stopped server, with `-WhatIf` to preview its exact targets. It refuses
cleanup during a pending RSW reset or through filesystem links/junctions.
Wild/player/shop data and the active RSW worlds are not backup cleanup targets.

## Console compatibility

The installer merges two server-only settings, preserving other local settings:

- `lithium.properties`: `mixin.util.block_tracking=false`. Lithium's block
  tracking predicates reflect on BetterEnd/BCLib methods whose signatures
  reference absent client-only classes on a dedicated server. Disable this
  optimization and its dependent optimizations, retaining vanilla behavior
  and the other Lithium optimizations. Do not hide or filter warnings.
- C2ME `[threadedWorldGen]`: `enabled = false`. BetterEnd's End spike generation
  writes a shared BCLib world-config temporary NBT file; concurrent workers
  race when replacing it. Keep generation serial rather than risking config
  loss. Other C2ME modules and user tuning remain unchanged.

These are stopped-server policy patches, not replacements for personal client
optimization configs.

GrimAC's bundled PacketEvents also reported a biome-registry parsing failure
for the custom `betterend:amber_sphere` particle. This is separate from the
Lithium class warnings and C2ME save race. Anti-cheat is not silently removed
or logging-suppressed; this remaining compatibility problem requires a
compatible upstream parser or an explicitly approved change.

## Lootr and BetterEnd

Extend Lootr's supported `lootr:convert/chests` and `lootr:convert/barrels`
block tags with all ten BetterEnd wood variants each. Vanilla entries remain.
Lootr converts only containers still carrying a loot table, preserving that
table/seed and providing separate player inventories. Player-placed storage
and chests whose loot has already been materialized are not converted.
Eligible existing containers convert when loaded; no world reset is needed.
Converted containers use Lootr's blocks/appearance, not BetterEnd's wood skin.

The isolated runtime test covers all 20 variants, preservation of player
storage, loot table/seed retention and two independent player inventories,
alongside the real RSW True Ending dragon and BetterEnd biome tests.

## Installation and preferences

Existing Prism players keep their instance and press Play. Client updates
remain client-only; personal options, keybindings, resource-pack choices,
server lists and Default Options journals are not replaced.
The public all-in-one ZIP is only for new installations.
Apply the server payload stopped; the installer does not start the server.

## Verification

- All 39 GoldClaim unit tests passed.
- Real isolated runtime loaded BetterEnd, BCLib, Lootr, Lithium and C2ME;
  all 20 container variants converted, personal storage stayed intact, two
  players received independent loot, and True Ending's 300-HP dragon spawned.
- A full Fantasy/Multiworld reset regenerated all three RSW worlds with one
  new seed and removed its temporary transaction. No Lithium class-analysis
  flood, BetterEnd NBT save race or reset error appeared.
- Packaged installers passed two-generation backup limits, selective config
  merging and preference/world/player/shop/Waystones state preservation.
- Two actual headless Packwiz client updates preserved preferences and
  skipped server-only mods.
- Applied to the stopped production server without an End reset: 359 existing
  player/shop/registry/journal/config/active-RSW files remained byte-identical.
  Removed all ten historical RSW archives (5.00 GiB), old RSW-only Waystones
  backup regions and excess backups in other categories. Two update-file
  backups remain. The server was not started.
