## Waystones throughout RSW and existing Wild cleanup

Server-only GoldClaim 1.0.33 enforces the policy in RSW Overworld, Nether and End:

- Reject player placement, commands/world-chunk writes, block interaction and
  Waystones item use in RSW.
- Cancel ordinary Waystones teleports both into and out of RSW, covering stones,
  warp stones, scrolls, plates and inventory-button travel.
- Remove existing RSW Waystones blocks without drops. Deferred chunk-load cleanup
  also removes structures generated into newly loaded RSW chunks.
- On the next startup, create a one-time cleanup plan for existing Wild stones
  that **no player has activated**, including all offline player NBT files.
  Preserve every Wild stone activated by at least one player.
- Future Wild placements are not automatically removed. Activation during the
  initial cleanup protects a queued Wild stone before its removal.

Cleanup processes one registered stone per server tick, including unloaded
locations, and separately one loaded RSW chunk per world tick. Original
waystone registry and affected region/entity/POI files, including external
chunk files if present, are copied before removal to
`backups/waystones-policy-v1.1.5/<level-name>`. This separate backup category
is outside the world directory and is not pruned by policy-update retention.
Both halves of tall stones are removed; single-block plates remain single-block
operations. Modified chunks and registry are saved before the completion marker.
The plan resumes after an interrupted cleanup; completion prevents repeated Wild
deletions on later restarts. Unreadable/corrupt activation data, malformed IDs or
backup failures abort explicitly instead of treating players as unactivated.
Offline player data is only read, never rewritten by this policy.

## Client and server delivery

Existing Prism users keep their instance and press **Play**. The unchanged
prelaunch command runs Packwiz with `-s client`, excluding GoldClaim and Gang
Shop. Personal options, keybindings, resource-pack selections, saved server
lists, player-added mods and Default Options journals remain untouched.
New first-run settings still use Default Options only for missing files.
No new personal mod configs are promoted into pack-managed settings.

The public all-in-one ZIP is for new installations, with a separate stopped-server
payload and installer. The server installer backs up replaced files, installs
the twelve additions/dependencies plus the two updated server-only mods, validates
their installed hashes, and preserves existing worlds/configs and shop data.
It never starts or restarts the live server.
