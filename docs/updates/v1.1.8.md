# v1.1.8: RSW End exit fix, server-wide HARD difficulty and item recovery

## RSW End exit portals

### Bug

In RSW End, the exit portal on the main island (after the dragon) and End
portals inside modded structures sent players into or under the bedrock of
the RSW Overworld. Players then suffocated or fell into the void.

GoldClaim 1.0.35 redirected End-to-Overworld travel from `rsw_the_end` to
`rsw`. Without a usable respawn point, it picked the landing spot with
`getTopPosition` on an RSW chunk that was not loaded yet. Unloaded chunks
report the world bottom (Y = -64), so the player was placed in or under the
bedrock.

### Fix (GoldClaim 1.0.36)

- If the player has a valid RSW spawn point (bed or anchor in `rsw`, checked
  the same way vanilla respawn does, inside the world border and build
  limits), the portal sends them there. The destination area is loaded first.
- Otherwise, the existing safe-ground search used for first RSW entry runs
  near 0,0. The player stays in the End until it finds solid ground, then
  arrives there. They see: `[RSW] No valid RSW spawn point; finding safe
  RSW ground near 0,0.` The search is cancelled if they leave the End.
- If RSW is closed, the player stays in the End and gets a rate-limited
  message.
- Vanilla removes a player from their world before asking for the portal
  target. GoldClaim therefore handles the whole End to RSW transfer itself,
  so no player is ever left half-transferred.

Nether portals and Wild/original-dimension behaviour are unchanged.

## Difficulty: HARD everywhere, `/difficulty` is server-wide

- `server.properties` is set to `difficulty=hard`. It drives Wild Overworld,
  the hub and the closed original Nether/End.
- Every `config/multiworld/worlds/**/*.yml` gets `difficulty: HARD`. These
  files are the RSW, RSW Nether, RSW End and PvP worlds. Each file is backed
  up first, and only that line is replaced or appended.
- GoldClaim 1.0.36 keeps every loaded world, including Fantasy runtime worlds
  and newly reset RSW worlds, at the server difficulty. It checks every
  second and runs immediately after `/difficulty`. Players get the updated
  difficulty shown on their client.
- `/difficulty <level>` now changes every world at once and is saved to
  `server.properties`, so it survives restarts. Only the `difficulty=` line
  is rewritten.
- Per-world `/mw difficulty` changes are overridden within about one second.
  Use `/difficulty` instead.

## Kunoisback item recovery

Kunoisback lost everything he was carrying in an RSW death caused by this
bug. RSW has no backups, so the items were reconstructed from his playerdata
snapshot from the start of his session. It was pinned by SHA-256 inside the
`policy-v1.1.7` update backup. The user approved restoring all items that
were missing.

- The offline tool `tools/gangs-player-recovery-1.0.0.jar` runs from the
  stopped-server installer. Like the v1.1.7 teleport purge tool, it is
  server maintenance only, never a mod or a client file.
- It delivers **28 stacks** in two named shulker boxes, "Kunoisback recovery
  1/2" and "2/2", in his Ender Chest. If the Ender Chest is full, they go
  into his inventory instead. Worn armour and trinket items are included.
  Item NBT (enchantments, durability, names) is kept from the snapshot.
- Excluded:
  - Item types he already holds again (to avoid duplicating what he
    recovered or re-obtained).
  - Nature's Compass, because that mod is no longer in the pack.
  - Any backpack whose storage UUID already exists elsewhere, so a backpack
    cannot be duplicated.
- Safety:
  - It refuses to run while the world is locked, and it checks that the
    player UUID and snapshot hash match.
  - It backs up his current `.dat` and `.dat_old` and the source snapshot
    into the update-backup generation. It writes atomically, verifies that
    all other player data is unchanged, then writes a marker
    (`world/goldclaim-recovery/kunoisback-20261014.done`) so it never runs
    twice.
- If it cannot run (for example, the snapshot or the player data is
  missing), the installer prints a WARNING with a rerun command and installs
  everything else.

Ledger stopped recording after 2026-10-13 16:04. Pickups and drops after
that time cannot be cross-checked.

## Updating

- Clients: the GoldClaim Packwiz entry is `side = "server"`. Pressing Play
  in the existing Prism instance updates the pack metadata to 1.1.8 and
  downloads nothing new. Personal options, keybindings, resource-pack
  choices, server lists and Default Options journals are never replaced.
- The public ZIP is for new installations, not a required reimport.
- Server: stop it, then run `server-update/Install-ServerUpdate.ps1
  -GameDirectory <server>`. This needs Java 17 or newer; pass
  `-JavaExecutable` if Java is not on PATH. The installer:
  - replaces GoldClaim 1.0.35 with 1.0.36;
  - applies `difficulty=hard` and the Multiworld world difficulty;
  - runs the recovery tool;
  - never starts the server.
  Do not pass `-ResetRswEnd`.

  recovery tool's plan, exclusions, idempotence and safety checks.

  - all earlier preservation checks and the rerun.
