# v1.1.7: GrimAC removal and original-dimension lockdown

## Investigation and decision

The installed GrimAC Fabric 2.3.74-8eb5f28 bundled PacketEvents
2.13.1+4d40422-SNAPSHOT. On player login, its biome registry decoder rejected
BetterEnd's `betterend:amber_sphere` particle type.

Checked the latest official Fabric Minecraft 1.20.1 build available on
October 13, 2026: GrimAC 2.3.74-f5bbe9c (October 7), bundling PacketEvents
2.14.1+b1f9403-SNAPSHOT. Verified its official download hash and exercised its
particle NBT codec in a standalone Java fixture using the Minecraft 1.20.1
protocol version and default particle registry. Vanilla `minecraft:ash`
decoded successfully; `betterend:amber_sphere` failed with the same
`Can't find ... in minecraft:particle_type` error. This was a codec test,
not a live-server startup or a full candidate login test.

A simple update is therefore not a verified solution. The user approved
removing GrimAC while keeping BetterEnd and GoldClaim, rather than suppressing
the warning or changing world content.

Sources:
- [Official Fabric 1.20.1 candidate](https://modrinth.com/mod/grimac/version/IwwpOU1A)
- [Candidate PacketEvents source commit](https://github.com/retrooper/packetevents/commit/b1f9403c4cc7843104809474b926be6a1945d9ad)
- [Particle registry decoder](https://github.com/retrooper/packetevents/blob/b1f9403c4cc7843104809474b926be6a1945d9ad/api/src/main/java/com/github/retrooper/packetevents/protocol/particle/type/ParticleTypes.java)

## What changes

- Remove GrimAC's both-side Packwiz metadata so the existing automatic client
  hook removes previously managed GrimAC on the next Play.
- Stopped-server and manual-client installers remove active/pending GrimAC
  JARs, backing them up using their existing update mechanisms.
- Strip GrimAC from all public ZIP mod folders and verify its absence.
- PacketEvents was bundled exclusively with GrimAC in the installed pack;
  removing that JAR also removes its active PacketEvents implementation.
  The unrelated BadPackets library is retained.
- Keep BetterEnd/BCLib, Lootr integration, GoldClaim, LuckPerms, worlds,
  inventories and anticheat configuration files. Only the explicitly targeted
  saved destinations and Waystone activation IDs are removed from player data.

**GrimAC's movement/combat cheat checks are disabled.** GoldClaim protections
and permissions are not an anticheat replacement; they continue protecting
claims and enforcing the pack's gameplay rules as before.

No End/Nether/RSW regeneration is needed. Previous backup limits and
Lithium/C2ME compatibility settings remain.

## Updating

Existing players keep their Prism instance and press Play. Client updates
remain client-only and preserve personal options, keybindings, resource-pack
choices, server lists and Default Options journals.
The public ZIP is for new installations, not a required reimport.
Apply the server update only while stopped; it never starts the server.

## Original Nether/End destinations

The confirmed scope is **only** `minecraft:the_nether` and `minecraft:the_end`.
Wild `minecraft:overworld`, the hub and all three RSW worlds remain accessible.
Portals in Wild may still be lit and are not extinguished.
The user confirmed there are no Sharestones; no new server-wide Sharestone ban
is added.

GoldClaim 1.0.35:
- Guards both server-player teleport overloads and dimension transfer. RSW
  portal destinations are redirected before applying the original-world ban.
  A higher-priority MixinExtras wrapper runs before Phantasm's vanilla-End
  cutscene wrapper. Real portal round-trips exposed that a plain HEAD hook
  runs too late: Phantasm otherwise intercepts the request before redirection.
  The final transformed bytecode and actual RSW Nether/End round-trips were
  verified. MixinExtras 0.4.1+ is declared explicitly and is already supplied
  by the pack's Fabric Loader.
- Rejects vanilla `/tp` with a command error rather than false success, even
  for operators. GoldClaim `/home` and public homes reject stale forbidden
  destinations explicitly.
- Cancels normal Waystone travel into the originals. The lower-level player
  guard also blocks Waystones' forced teleport API, which bypasses its normal
  cancellable event.
- Rejects new respawn points in the originals. On join, respawn and player
  maintenance, players found there are moved to the configured hub without
  changing inventory/experience. If the hub cannot be reached, an explicit
  error and disconnect prevent leaving the player trapped.

The stopped-server installer runs the separately packaged Java 17+
`tools/gangs-teleport-purge-1.0.0.jar`; this is an offline data tool, not a
server mod or client update. It uses Adventure NBT 4.26.1 and Gson 2.10.1,
without launching Minecraft. Supply `-JavaExecutable` if Java is not on PATH.

Its preflight reads all candidate files before mutation. It removes:
- GoldClaim saved homes/public homes and return records whose `worldId` is
  one of the two closed IDs.
- Essential Commands homes, warps, spawn and `/back` records whose
  `WorldRegistryKey` points there, including offline mod-player/profile files.
- Original-dimension Waystone registry entries and their UUIDs from every
  offline player's activated list, including the corresponding `.dat_old`.
- Original-dimension bed/anchor respawn points and recovery-compass death
  locations. Logged-out players' saved dimension/position is not rewritten;
  GoldClaim evacuates them on their next join.

Unknown NBT, inventory, experience, allowed destinations and allowed
activation IDs are retained. Unchanged files are not rewritten. Graves and
their contents are not deleted; the destination guard prevents teleporting
into the originals through grave commands as well. Personal client map
bookmarks/configs are not replaced.

Before applying changes, the tool protects changed metadata and only the
specific original-world region/entity/POI files containing affected stones
in the existing update-backup generation. It does not back up RSW.
The two-generation policy still applies.

Registry/list removal happens while stopped. Physical block positions are
persisted in a separate restart-safe cleanup plan. On the next user-started
boot, GoldClaim removes both stone halves without drops, saves the affected
original chunks, then deletes the plan. It does not generate absent chunks
just to clean stale registry entries. A stopped-server installer rerun is
idempotent and preserves a pending physical-cleanup plan.

No original or active RSW world folder is deleted, regenerated or reset.

## Validation

- Checked installed mod manifests: no other top-level Fabric mod requires
  GrimAC or PacketEvents.
- Verified that GrimAC was the sole active PacketEvents owner in production.
- Packaged installer fixtures cover removal on both sides, pending server
  JAR removal, reruns, and preservation of content mods, BadPackets,
  configuration, player data and world/reset state.
- Two actual Packwiz generations exercise removal of a previously managed
  both-side GrimAC fixture while retaining personal preferences and skipping
  server-only mods.
- Seven additional unit tests (46 total) cover exact dimension matching, homes/warps/back,
  unknown/player data retention, JSON destinations, offline activated IDs,
  registry removal, originals backup, dry-run behavior and idempotence.
  Both current compound and older list-form Essential Commands homes are covered.
- Isolated real Minecraft/Fantasy/Multiworld/Waystones tests exercise both
  teleport overloads, real stale/allowed `/home` commands, operator `/tp`,
  ordinary/forced Waystone attempts and round-trip RSW Nether/End portals,
  physical removal in both originals, hub recovery and allowed Wild/RSW
  travel. This is server-API verification with fixture players, not a live
  multiplayer login test.
- The existing BetterEnd/Lootr, True Ending dragon, Macaw's shop and full
  synchronized RSW reset fixtures remain enabled.
  They passed with production Fabric Loader 0.19.3 / MixinExtras 0.5.4,
  as well as the development Loader 0.16.14 / MixinExtras 0.4.1.
  On Windows, the reset fixture encountered temporarily locked C2ME region
  handles; existing fail-closed recovery retried successfully, completed the
  synchronized reset and deleted temporary staging. This is not described as
  an entirely warning-free boot or a change to production reset behavior.

The stopped-server preflight identified **165 original-dimension Waystones**
and **11 GoldClaim homes** for removal. Seven players have affected saved
activation lists (14 files including `.dat_old`). Essential Commands records
contained no matching original-world destinations. Production is not started
by the installer or release workflow; physical cleanup remains pending until
the user starts it.
